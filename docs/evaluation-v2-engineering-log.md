### 术语速查

| 名称 | 在本项目中的具体含义 |
| --- | --- |
| case / 任务 | 一份固定的有缺陷代码、公开说明、可见测试和评测专用资产 |
| trial / 一次独立运行 | 从干净输入重新启动修复；每题 3 个 trial，不是将同一补丁验收 3 次 |
| attempt / 修复尝试 | 同一 trial 内，最多 3 次；每次恢复 baseline，再带着失败反馈重新修复 |
| 公开任务说明 / contract | 输入输出和业务规则，例如“加急运费 15，非加急 5，与重量无关”；不是答案补丁 |
| gold / 参考补丁 | 端到端修复时不给 Repair，用于独立预检且不要求逐字匹配；固定 Review 对照若把它选作当前待审候选，其 Diff 会输入，但不附正反标签或其他候选答案 |
| hidden tests / 隐藏测试 | 由独立 grader 使用、不提供给 Repair 或 Review 的验收测试；不等于任务本身是未见数据 |
| grader / 独立验收器 | 在全新副本上应用补丁，再跑可见和隐藏测试，不直接相信 Agent 的 success |

## 01｜先建立可信的离线评测链路

日期：2026-10-15 初始验收。

**问题。** 原有 15 个单 Bug 样例不能回答“是否过拟合可见测试、能否同时修改多个模块、重复运行是否一致”。Agent 的成功状态也不等于独立验收成功。这些是评测能力缺口，不是已发现模型作弊。

**处理。** 保留旧 v1 成绩；增加 v2 独立入口。15 个原有任务补充公开说明和私有验收资产，新增 3 个多文件任务。每题预检包括：buggy 失败可复现、原本通过的测试不退化、参考补丁通过验收、过拟合错误补丁通过可见测试却被隐藏测试拦住。

**验证。** 当时离线测试 288 passed、1 deselected；18/18 任务包有效。补丁拒绝、缺失/跳过测试、超时、产物恢复、源码指纹变化和未知成本均有覆盖。

**边界。** 没有新增真实开源缺陷、容器隔离或冻结 holdout；预检通过不是模型答题通过。

证据：[初始验收记录](evaluation-v2-verification.md)、[v2 使用说明](evaluation-v2.md)。

## 04｜首次 18 题全量出现记录器错误

日期：2026-10-15。

**现象。** case_02、case_07、case_12 出现 `RecorderError`，未完成独立验收，残留 `trace.jsonl.tmp` 或 `pytest.log.tmp`。总体为 15/18（83.3%），不是“去掉环境问题后 100%”。

**已经知道的原因。** 运行产物写入失败。旧 worker 日志未保存底层异常链，无法仅凭残留文件确认 Windows 错误码或占用进程。

**采取的措施。** 保留全部失败产物，不用临时文件覆盖正式文件，不为这 3 题补跑以改写旧成绩；转入不调用模型的记录器复现。由于日志不完整，209,335 Token 仅为已知下界。

**同轮额外观察。** multi_time 经一次 Review 拒绝后生成了不同补丁，最终通过。这能说明反馈链路确实发生，不证明 Review 普遍提高成功率。

证据：[首次全量 15/18 报告](evaluation-v2-first-full-run.md)。

## 05｜离线复现并修复 Windows 文件替换路径

日期：2026-10-15。

**复现。** 真实 `RunRecorder` 连跑 30 组、每组追加 50 条事件，22 组完成、8 组失败；捕获到 `Path.replace()` 的 `PermissionError(errno=13, winerror=5)`。人为持有目标文件读取句柄也复现同类失败。

**结论边界。** 确认了可复现的文件替换拒绝访问路径；自然出现的占用来自哪个进程仍未知，也不能据此补认旧 3 题的底层错误码。

**修复。** `_atomic_write()` 只重试 Windows 错误码 5/32/33 的替换动作，最多尝试 5 次；等待 0.05、0.1、0.2、0.4 秒，累计上限 0.75 秒。临时文件只写一次，不降级成非原子覆盖。其他写入错误及时抛出；永久失败保留异常链和临时文件。没有修改 ACL、所有者或关闭安全软件。

**补充可观测性。** worker 保存脱敏后的异常类型、消息、原因链和错误码；限制链深度及消息长度，不输出环境变量全集、调用栈局部变量或真实凭据。

**验证。** 首批回归先 7 failed / 14 passed，修复后 21 passed。真实文件系统压力测试 100 组 × 50 条事件全部完成，逐条验证顺序和内容；实际触发 33 次重试。持有读取句柄的场景在释放句柄后也成功。

**不能宣称。** 两次压力测试规模和系统状态不同，不能计算严格的故障率改善；有限重试也不保证永久权限错误能恢复。

证据：[完整排障与验证](evaluation-v2-recorder-fix.md)、[记录器源码](../src/pyrepair/recorder.py)、[回归测试](../tests/test_recorder.py)。

## 06｜审查发现：异常详情可能在二次采集中丢失

日期：2026-10-15。

**现象。** 若 `worker-error.json` 自身写失败，子进程仍在 `agent-result.json` 保存了错误，但父进程再次采集时忽略该备用字段，随后覆盖摘要，导致诊断丢失。

## 13｜历史“通过”补丁仍有精度缺陷，不能直接当作正确标签

日期：2026-10-16。

**发现。** 准备作为 Review 正例的 case_15 / trial 1 最终补丁使用 `int(Decimal(value.strip()) * 100)`。公开说明要求非负、最多两位小数金额精确转整数分，没有限制金额位数。

**证据。** 将历史 fix.patch 应用到新建临时公共仓库副本，导入修改后的真实 money.py，比较函数结果和基于字符串拆分、整数运算的期望值：

| 输入 | 原候选（Decimal 精度 28） | 精确期望 | 只将精度改为 64 |
| --- | ---: | ---: | ---: |
| 12.50 | 1250 | 1250 | 1250 |
| 0.29 | 29 | 29 | 29 |
| 12345678901234567890123456789.01 | 1234567890123456789012345679000 | 1234567890123456789012345678901 | 1234567890123456789012345678901 |

**原因。** Decimal 从字符串构造值不等于后续运算无限精度；乘法受当前 context 的 28 位有效数字精度约束。这个输入的误差为 99 分。只改变 localcontext 精度后该反例消失，支持精度舍入为本反例原因。将精度固定提高到 64 仅用于诊断，不是对任意长度金额的通用修复。

**复现中遇到的工具问题。** 第一次将补丁原始 bytes 解码直接传入 apply_patch_checked，遇到 `patch does not apply`。文件有 9 个换行，其中 6 个是 CRLF；正式 grader 使用 read_text 的通用换行处理。改为相同读取方式后成功应用并复现数值错误，没有改写原补丁。不能把首次诊断脚本的换行错误算成模型补丁不可用。

历史补丁 SHA-256：`1cd801643d84cc6788bce982a7d0e534d55a66087a0c9ca7528c4ddf7df223d4`；复现前后原文件字节一致。原始来源仍是 `live-repeat3-flash-20261016-df19fe71/trials/case_15/1/execution-1/agent/.pyrepair/runs/evaluation/fix.patch`。

**处理。** 不修改旧 54/54 结果或旧隐藏测试，不继续给该候选打“正确”标签。暂停固定样本准备，向用户请求选择：推荐保留三题，另存明确标为人工校准的正确候选、增加仅用于新 Review 评测的精度边界验证；也可先排除 case_15，缩为两题。两者都会写明新样本身份，不将人工修正宣传成模型生成结果。
