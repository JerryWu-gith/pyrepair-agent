# Evaluation v2：Windows 记录器离线修复

日期：2026-10-15。本文是工程故障定位与离线验证记录，**不是新一轮模型评测成绩**。

后续获准新建了 [修复后 18 题独立实跑](evaluation-v2-post-fix-full-run.md)，结果为 18/18；本文仍保留离线修复阶段的证据和当时尚未重跑的边界，两个阶段不混写。

## 为什么修

[首次 18 题单轮实跑](evaluation-v2-first-full-run.md) 的 3 个任务在记录产物时抛出 `RecorderError`，没有完成独立验收。历史 worker 只记录异常类型，无法从旧日志还原底层 Windows 错误码。

本次不调用模型，直接在同一台 Windows 主机反复调用真实 `RunRecorder`：

- 修复前：30 组，每组追加 50 条事件；22 组完成，8 组在 `trace.jsonl.tmp → trace.jsonl` 的 `Path.replace()` 处失败。
- 这 8 次离线失败均保留 `PermissionError`，`errno=13`、`winerror=5`。
- 人为持有目标日志的读取句柄时也复现同类失败。

因此本次修复针对的是**已复现的 Windows 文件替换拒绝访问路径**。尚未确定自然发生的文件占用来自哪个进程，也不能追认旧的 3 个任务一定具有相同底层错误码。没有调整文件所有权、ACL 或关闭安全软件。

## 改了什么

### 1. 记录器：只对替换动作有限重试

文件：`src/pyrepair/recorder.py`，`_atomic_write()`。

1. 临时文件仍只写一次。
2. 遇到 `PermissionError` 且 Windows 错误码为 5 / 32 / 33 时，重试 `replace`。
3. 最多 5 次尝试，4 次等待分别为 0.05 / 0.1 / 0.2 / 0.4 秒，总等待上限 0.75 秒（不含文件系统调用耗时）。
4. 成功前不改旧目标文件，不通过重复追加来重试，不降级为非原子覆盖。
5. 永久失败仍抛出 `RecorderError`，保留原异常链和临时文件。磁盘满、无 Windows 错误码的权限错误、临时文件写入失败均不进入这段重试。

这不改变模型提示词、Agent Loop、工具预算、候选补丁规则或验收标准；也不把单写入者记录器变成并发日志系统。

### 2. Worker：留下可诊断、已脱敏的错误

文件：`benchmarks/evaluation/agent_worker.py`。

- 异常边界记录类型、消息、原因链，以及存在时的 `errno` / `winerror`。
- 原因链最多 5 层，每条消息最多 2,000 字符；先脱敏，再截断；循环异常链不会无限遍历。
- 不记录调用栈局部变量、环境变量全集或 API 请求体。
- 控制台与 `worker-error.json` 保存脱敏诊断，`agent-result.json` 和父进程结果包含 `error_details`。
- 如果诊断文件写入失败，父进程从子进程摘要中的 `error_details` 找回原始异常；再次落盘、再次采集仍保留它。备用路径不信任摘要中的成功状态或用量，模型调用与 Token 仍根据原始事件统计。
- 错误仍计为 `status=error`、`usage_complete=false`；不把日志修复当作模型修复成功，也不把缺失成本计为零。
- 损坏的诊断文件保守记为 `invalid_worker_error_details`，不允许错误被恢复为通过。

错误示意（非真实用户路径或凭据）：

```json
{
  "exception_chain": [
    {"type": "RecorderError", "message": "写入运行产物失败：trace.jsonl: ..."},
    {"type": "PermissionError", "message": "...", "errno": 13, "winerror": 5}
  ]
}
```
