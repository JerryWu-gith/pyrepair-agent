## 2026-10-26：发现的问题及处理

| 问题 | 原因 | 处理与证据边界 |
| --- | --- | --- |
| 旧自建题汇总首次拒绝通过 | 部分旧 manifest 没列出测试文件中原已执行的 passing 节点，共 15 个；不是新测试失败 | 不删节点、不改旧题。校准审计仅对自建题接受选定文件内的额外基线 passing 节点，并冻结完整收集列表；正式评分检查收集集合一致 |
| 评分器曾可接受丢失额外 passing 节点的记录 | 历史合同仅约束 manifest 显式节点 | 先用自有数据复现，再校验冻结的 visible/hidden 完整节点集合；公开失败时仍允许不执行隐藏阶段，不把正常失败误报技术错误 |
| 评测入口原仅支持二十题 | 旧计划和 worker 权限上限为二十题实验设计 | 新增显式 `goldset50-r1`、版本 2 worker job；旧入口和旧 2,220 上限不放宽。共用监督、预算、日志和评分器，而非复制另一套协议 |
| 布尔值可冒充配置整数 | Python 字典比较中 `True == 1` | 新 profile 对完整配置执行严格 JSON 身份比较；旧约束保留 |
| 恢复评分可能制造新计时 | 原计时若在结果写盘后中断，恢复路径会给旧结果附上新时长 | 只对全新评分目录记录 monotonic 时长；恢复时无法证明原时长则保持 unknown，不覆写旧证据 |
| 长测试期间触发 runtime changed | 父代理当时仍在修改冻结清单覆盖的代码 | 拒绝属于预期保护；等待代码静止，只补跑受影响用例，不削弱哈希检查，不重复整套历史实验 |
| 临时目录/缓存权限错误 | 受限环境不能在默认 C 盘临时目录或 Ruff 缓存写入 | 为测试设置项目内独立 TEMP/TMP/PYTEST_DEBUG_TEMPROOT；Ruff 使用 `--no-cache`，不改 ACL |
