# 新增五题真实开源缺陷评测设计

日期：2026-10-25。状态：用户已同意五题阶段的口头设计并要求开始；本书面方案待审阅。当前只有来源核对，没有新任务的离线验收或模型成绩。

## 1. 目标和范围

新增五道真实历史缺陷，来自三个此前未纳入本项目评测的 Python 开源仓库。在固定 Agent 上执行 single-shot 与 full-agent 两种方法，每题每方法独立运行三次，共三十个方法运行结果。

已有二十题开发任务、历史原始结果及 59/60 对 36/60 的报告保持不动。新增五题单独报告，不写成已有二十五题未见验收。后续累计三十题包含本阶段五题，不是额外三十题；本文件只覆盖五题的交付。

这是一组面向本项目的新外部评测任务，不是模型训练数据干净性证明。制作评分资产需要阅读上游修复；这种阅读不等于把参考答案提供给被测 Agent，也不能据此称整个开发团队从未见过任务。

## 2. 已选择的方向

采用固定仓库快照、明确公开任务和独立测试覆盖层，在验证过的 Docker 环境执行。保留仓库布局和真实生产代码，不将函数抽出来改造成玩具题。优先复用现有资产验证、公开输入、评分和进程监督组件。

不采用两条替代路线：

- 抽取少量函数制作简化题：环境更容易，但不能证明真实仓库中的修复能力。
- 一边评测一边调 Agent：能改善开发集表现，但会改变被测对象。本阶段冻结 Agent；发现不足记录为后续优化，不在同一轮成绩中悄悄修复。

## 3. 候选和来源

五个候选及完整提交标识见 [候选核对表](../../external-pilot5-candidates.md)。目前分配为 Click 一题、python-dotenv 两题、packaging 两题，覆盖参数语义、编码边界、跨文件读写、哈希一致性和序列化语义。

基线取上游修复提交的第一父提交，而不是 PR 页面可移动的 base SHA。只有确认合并的修复才进入候选清单。源码归档、Git tree、许可证、文件摘要、公开覆盖层、参考补丁和校准反例均须登记来源。

这是偏小型、纯 Python 缺陷的工程试点，不宣称等价于 SWE-bench 或代表大型仓库长程任务。至少一题实际参考修复涉及多个生产文件；不把同一 Bug 的多个断言计成多道题。

候选在模型评测之前通过环境和任务质量预检才能纳入正式清单。不能因模型失败而换题。若候选因固定环境不兼容、复现不成立、许可或验收合同问题不合格，记录证据和排除原因，先补齐任务并重新冻结清单，再开始正式模型评测。不能用修改上游生产基线来消除环境问题。

## 4. 固定被测对象和编辑权限

Agent 生产代码以本阶段开始时的项目提交 `7c9508e63ff3a133e7599b3a2ca439e935f10295` 为依据；记录 `src/pyrepair/`、`pyproject.toml` 及实际运行配置的摘要。评测基础设施可以为新任务接入而修改，但须单独记录和冻结其最终运行时身份。

不修改修复提示词、Review 提示词、工具语义、上下文预算、Policy Gate 或 Agent 重试策略。需要改变这些部分才能修题时，按被测能力不足记录，而不是为了本轮结果临时放宽。

新任务的允许编辑范围按其包源码根下所有现有生产 `.py` 文件列举，不按参考补丁碰巧修改的文件缩窄。两种方法和 Review 获得相同范围说明。仍不允许修改测试、配置、依赖和环境，也不增加本轮工具无法完成的新增文件要求。报告明确这是受控编辑范围下的修复，不是无限制软件工程评测。

## 5. 数据流和隔离

1. 来源准备：固定提交归档与 Git tree 对照，读取为数据，不在宿主导入或执行上游代码。
2. 任务准备：保留缺陷仓库布局，加入公开失败复现和不含修复线索的任务说明；登记所有新增或排除项。
3. 离线预检：缺陷基线、参考修复和人工不完整补丁分别进入无密钥 Docker 测试环境。
4. 冻结输入：记录源码、公开任务、测试集合、环境、提示词、方法配置和运行顺序的摘要。
5. 候选生成：可信侧持有模型密钥；模型只接收公开任务、公开故障与公开上下文。测试执行留在无密钥、禁网的容器侧。
6. 独立评分：候选冻结后才加入隐藏验收，评分结果不返回候选生成流程，也不注入下一次独立运行。
7. 汇总报告：收集全部预定运行，不挑成功产物、不覆盖失败，不把技术错误包装成已验收补丁。

公开输入不得含参考修复、私有测试、上游 PR 的修复解释、修复提交日志、Git 历史或上一遍的补丁和评分。`TASK.md` 由公开问题行为整理，不能复制 PR 中的 root cause/fix 部分。

## 6. 环境接入

先检查现有固定 Python 3.13 Docker 环境是否能承载这些仓库，不预先承诺全部兼容。三个候选仓库均采用 `src/` 布局；当前容器入口只显式加入仓库根，因此须核对上游 pytest 配置及导入路径，不能误把宿主已安装的同名库当成候选源码。

如需 `src/` 导入支持，由可信评测协议明确描述并限制在冻结仓库内部，Agent 无权改导入根或配置。测试必须核对模块实际来源路径。新增协议字段需要同步校验器、容器入口、环境摘要和测试；旧评测包继续使用旧身份，不就地改写旧环境锁。

如果需要新依赖，使用有哈希的固定依赖构建新环境，保留旧环境；不在评分时联网安装，不允许上游构建钩子在宿主执行。测试执行超时仍分类为超时，不静默提高超时以改变正式结果。

## 7. 独立评分和预检条件

每题必须有公开失败复现、隐藏功能断言和明确的原有行为回归范围。核心 F2P/P2P 节点必须先收集再冻结。

- 缺陷基线：声明的 F2P 节点失败，P2P 节点通过。
- 上游生产参考修复：全部核心 F2P/P2P 节点通过。
- 人工不完整补丁：公开复现通过，至少一项合理隐藏边界失败；明确标成人工评分器校准反例，不算模型运行结果。
- 不接受因测试无法导入、未收集、环境错误或跳过而得到的假阴性/假阳性。
- 判分按行为，不要求候选 Diff 与上游参考修复相同。
- 扩展回归只运行事先声明且环境支持的上游测试范围，独立列出节点数、跳过及未执行，不将局部回归写成全仓全量。

任务自有边界测试用于补充遗漏，不追加公开任务未要求的新业务合同。若发现测试合同错误，保留旧资产并创建新修订；正式结果不可混用不同任务修订。

## 8. 独立重复与方法配置

使用 `deepseek-flash`、现有 thinking/reasoning 配置和现有 two-method 协议。single-shot 每个运行只有一次生成；full-agent 每个运行最多三轮修复，每轮八次工具调用、最多十一轮模型响应，仍有独立 Review。

五题 × 两方法 × 三次独立重复 = 三十个预定结果。每个运行重新创建 worker、模型客户端、运行状态和工作区；仅共享只读的冻结公开输入和同一实验的计量账本。禁止共享聊天、候选、私有评分或前一次运行的结构化反馈。同一 full-agent 运行内部按现有设计传递跨 attempt 的结构化反馈。

执行顺序沿用现有 `paired_slots` 的两方法交替顺序。全部独立重复纳入汇总，不只补跑失败题；断点恢复只执行未开始槽位，不重复已经发起但状态不明的请求。

用户不要求以费用或调用量缩小本阶段规模。仍记录用量，并用有限实验身份限制失控执行：三十个正式槽位最多 555 次现有口径的模型调用预留（15 个 single-shot × 1 + 15 个 full-agent × 36）。这不是人民币上限或真实 HTTP 次数预测，不要求花满。无需为了费用另行缩减任务。API 响应解析、运行协议或环境的技术错误停止并记录；模型输出不是有效补丁、Review JSON 不合格导致默认拒绝等候选失败仍按现有方法规则处理，不能借此额外补请求。普通修复失败继续后续预定槽位；不自动技术重试或额外冒烟付费调用。

## 9. 基础设施边界

当前 `live_plan.describe_plan` 和 worker 校验绑定固定二十题、三次重复；来源登记只接受旧两道真实题。新增五题不能仅修改 manifest 后就假装已有入口可直接运行。

增加外部任务的明确入口和冻结实验身份，复用现有 slot、worker、评分、journal 与监督组件；旧二十题入口和旧包校验保持原约束。注册新来源时保留仓库/提交白名单和按字节核验，不将入口放宽成任意仓库脚本或宿主执行器。为新协议编写定向测试，不进行无关架构重构。

## 10. 报告、记录和完成条件

每题分别提供来源、预检结果、公开/隐藏/回归范围、三次双方法结果、模型用量、方法耗时、独立评分耗时及失败分类。主要数字是每方法十五次运行的核心验收成功率；另报每题 0/3 至 3/3 和三次全部通过的题数。三次重复不是十五种独立缺陷，不根据五题推断通用成功率或强统计显著性。

这是不同调用量的整体工作流对比，不是等算力比较或某一组件的因果消融。格式错误、补丁无法应用、规则拒绝、Review 拒绝、功能失败、回归失败和技术错误分别记录。

新工程记录存放在 [本阶段日志](../../external-pilot5-engineering-log.md)。每步记录目标、现象、证据、原因、处理、验证、遗留；不记录密钥。

交付完成须同时满足：五题来源核验和离线预检通过；三十个预定槽位全部有可解释终态；评分和用量可追溯；失败保留；Agent 源码冻结未被任务驱动修改；旧结果未被覆盖；正式报告明确适用边界。技术停止时只能交付阶段进展，不能称五题评测已完成。

本阶段不自动推送 GitHub、不创建 PR、不更新简历成绩，也不启动后续二十五题。
