前置：[分层验收已批准设计](2026-10-23-layered-acceptance-design.md)、[离线验收报告](../../fair-workflow-comparison-offline.md)。已有20题核心校准、120脚本槽位、869项离线回归与1项实际Docker/FakeLLM集成，不是模型修复成绩。

## 1. 目标与现状

目标是使真实 single-shot 与 full-agent 能通过同一受控入口执行已冻结的方法计划，复用已验收的公开输入、调用额度、恢复规则和分层独立评分，而不是绕过旧 live 安全门。

源码核对：run_comparison.py 只有 prepare/verify/simulate；comparison_methods 不加载凭据、不构造提供方；旧 agent_worker 与 require_live_cases 仍拒绝真实开源任务。现有配置将每次 single-shot 限1次ModelClient调用，完整Agent将Repair与Review合计限36次；SDK和客户端额外重试在对照侧均为0。

## 3. 入口和权限边界

新增独立的可信控制器入口，不给现有 simulate 增加隐式真实模式；不放开旧 run_evaluation/agent_worker 的开源 live 拒绝。新增模块限 benchmarks/evaluation、独立CLI与测试，本轮不改 src/pyrepair 或 Docker安全配置。

默认行为为 inspect/validate，仅检查执行计划；真正执行必须显式指定运行模式、已批准的执行清单、调用总上限及全新输出目录。清单至少绑定：冻结包哈希、模式smoke/formal、精确slot列表及原顺序、模型/端点、逐槽位和全局调用限制、零重试、worker1800秒上限、环境身份、来源和输出身份。没有有效清单不能读取密钥或构造提供方。

执行清单是防误操作的本地约束，不宣称能抵御恶意宿主篡改。人类授权来自对话中的明确确认；不能由程序自行生成一份清单就推断已经获得授权。

沿用已冻结的 deepseek-flash / https://api.deepseek.com / thinking enabled / high 设置，不静默切模型。API key仅在明确批准真实执行后从DEEPSEEK_API_KEY环境变量获取，不自动读取.env、命令行传key、写入job JSON或打印到日志；环境变量缺失就停止，不做试探性请求。这个阶段不要求用户在聊天里再次粘贴密钥。

## 4. 控制器、worker和Docker的数据边界

```text
可信控制器：核对执行清单/冻结身份/额度
    └─ 当前槽位的公开job → 有时限的可信worker
          ├─ single-shot：GuardedClient → 一次响应 → candidate.json
          └─ full-agent：现有Coordinator + Docker公开测试工具 → candidate.json
候选返回控制器 → 同一grade_layered → 核心结果 + 独立扩展结果 → journal/报告
```

worker只接收当前公开仓库、PublicTaskSpec、冻结公开证据、方法/输出/共享额度位置及固定模型设置；不接收EvaluationCase、完整manifest、私有指纹清单、隐藏节点/测试、gold/wrong或独立判分结果。full-agent仍使用现有方法、完成规则和工具，不让模型执行任意宿主命令。

真正连接模型的进程是受控可信worker，不是执行上游代码的容器。上游源码/测试只在既有受验Docker内运行；容器无外部网络、无API key、不回退宿主。核心/扩展验收仅由控制器持有私有资产，且扩展副本不安装隐藏测试；完整扩展名单从冻结的collection.json取，不能重新依据候选收集后缩小验收。

## 5. 调用、时限、错误和恢复

所有角色共用现有CallBudget/GuardedClient。每次调用前持久化预留，返回立即保存响应；客户端与SDK重试均为0。单次补丁1次；完整工作流最多36次（含Repair/Review），不增加已有attempt/tool/turn上限。预留数是保守ModelClient调用额度，不冒充人民币上限或实测HTTP传输次数。

每次方法运行用独立worker进程执行，最长1800秒。父进程应停止自己启动的进程树，随后根据可信worker目录记录的确切CID及所属身份检查并清理仍存活的本次容器；不得docker prune、全机停止容器或清理其他会话资源。清理不完整或身份不符即技术错误并暂停。启动容器、模型调用及阶段超时沿用已批准限制，不自动提高时限。

API/响应协议/worker/容器基础设施错误保留已预留调用、已保存响应及候选，暂停后续调度；失败用量未知不能记0。不自动重试、重启worker或补一次模型响应来填同槽位。

恢复仅继续已保存的本地处理：single-shot唯一已存响应可以本地解析；已有合法候选可以按既有状态机独立判分；full-agent中断且没有候选则记技术中断，不伪装成可继续的会话。已终态的技术失败保持暂停，不篡改journal刷新分数。实际worker异常/超时与正常结束后候选/格式失败必须区分，不能把网络错误当成普通不通过继续花额度。

## 6. 分阶段执行及次数口径

后续推荐真实冒烟预先固定为more r2、trial1、两个方法各一次，保持它在冻结计划中的方法顺序；输出为独立smoke实验，不混入正式三次重复成绩，不根据结果改选题。

- 冒烟：2次方法运行，最多1＋36＝37次模型调用预留，不是37元。
- 正式：20题×3trial×2方法＝120次方法运行；single-shot60次×1＋full-agent60次×36＝理论最多2,220次模型调用预留，不是120次请求，也不是2,220元。
- 冒烟与正式的预算、输出和journal完全独立。旧72次Review授权已结束，不复用；本设计尚未批准37或2,220次真实额度。

费用目前不做猜测。真实执行前须再次说明实际批准的是调用额度还是人民币边界；如要求人民币硬上限，需要另外核实价格并设计可验证的费用约束，不能把现有调用计数器说成已实现现金硬限额。缺失usage保留unknown与已知下界。

## 7. 冻结与离线验收

新入口和worker进入运行源码身份。现有lp-1023-74d56f08及120槽位模拟保留为历史已验收快照，不篡改其授权字段或源码摘要；实现稳定后创建新包，完成相同20题离线校准与冻结核对，再提出真实冒烟预算确认。离线构建不等于自动启动真实执行。

离线验收要求：

1. 缺少/篡改授权、包、模型、顺序、额度或环境时，在凭据读取和客户端构造前拒绝；inspect没有API副作用。
2. 用自编worker/FakeLLM覆盖single-shot、完整工作流、独立分层判分与分角色额度；控制器材料不能进入worker模型输入。
3. 预留之后中断、响应之后崩溃、worker超时、容器残留、API错误、恢复与额度耗尽都有反例；不重发请求、不接受另一候选成绩。
4. 单独实际Docker/FakeLLM检查新进程装配及清理，绝不以真实API代替接线测试。
5. 一次集中完整离线回归、静态检查与限定独立审查；生产源码、旧任务、失败目录与历史成绩保护不变。
6. 日志记录每项问题/原因/修复/证据；报告按全部计划槽位保留技术错误、未运行和未知费用。没有真实执行就不产生性能数字。
